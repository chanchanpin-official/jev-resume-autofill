## 公开示例与本机真实资料

`profile/profile.example.json` 始终为 `{}`。`docs/examples/profile.synthetic.json` 是独立的纯虚构教学示例，不是把作者姓名替换后保留原经历的简历；邮箱为 `example.invalid`，不包含可联系的电话、住址、生日或证件号。启动过程不会把它复制为用户 profile。

真实资料仅写入被忽略的 `profile/`，配置与运行数据写入 `.runtime/`；`extension/local-config.js` 也被忽略。打包脚本排除这些文件。Git 忽略规则不是加密或防泄露机制：不要强制添加私有文件，也不要把个人资料复制到 `docs/`、`tests/` 等公开目录。

填写时，相关候选事实、字段和岗位上下文仍会发往使用者自己配置的模型服务。这与“公开仓库没有作者个人资料”是两个不同范围，详见 [README 的资料与隐私说明](../README.md#资料与隐私)。

## 后续复核方式

在仓库根目录执行：

```sh
python3 -B scripts/audit_public.py --tracked
python3 -B scripts/audit_public.py
python3 -B skills/jev-profile/scripts/validate_profile.py docs/examples/profile.synthetic.json --require-facts
npm run package
```

前两条分别检查 Git 跟踪文件和打包文件；扫描器发现疑似手机号或证件号会阻止通过，测试中故意无效的全零数字除外。示例校验已加入 CI，空默认模板仍有回归保护。

个人专项扫描可使用 `--deny-file <本机私有JSON路径>`。该文件为真实身份标识组成的字符串数组，仅留本机；扫描失败输出文件与类别，不回显命中值。上述命令不会自动检查 Git 历史或已经发布的附件，历史与附件需要单独取回比对。本次已完成这两项检查，后续发布不能仅凭当前工作树通过便断言历史与旧附件安全。
