# 0.2.4 首次初始化验收

检查日期：2026-10-13。此记录对应 0.2.4 源码与安装包的验收范围；安装包和发布状态见 [v0.2.4 Release](https://github.com/chanchanpin-official/jev-resume-autofill/releases/tag/v0.2.4)。

## 初始化流程

| 阶段 | 实现与成功标准 |
| --- | --- |
| 安装 skill | `install_skill.py` 只复制必需文件，支持含空格路径、重复安装和更新备份；发现旧默认位置时阻止重复安装。用户仍需确认 agent 已发现 `jev-profile` |
| 配置个人 API | `configure.py` 在用户自己的交互终端收集 Jev / LLM 参数；密钥不回显，不接收聊天或管道代填。缺少必需项时不覆盖原配置；环境覆盖会明确提示 |
| 创建个人 profile | skill 从授权材料建立来源清单、事实及待确认事项，校验后保存到实际使用的 profile 路径。教学示例不能充当用户履历，事实正确性仍由本人核对 |
| 本地自检 | `doctor.py` 检查有效配置、密钥文件、非空 profile 及格式，不调用模型；未完成项返回非零退出码 |
| API 实测 | `--probe-models` 仅发送固定虚构内容，检查 Jev 匹配与所选 LLM 协议、JSON 和来源引用。执行前说明可能产生少量费用，不发送用户 profile |
| 服务配对 | `--bridge` 核对令牌认证、源码版本、profile 路径及服务中的有效配置，识别旧服务或环境不一致 |
| 浏览器验收 | 加载 / 重载扩展后，在设置页检查连接。旧配对可通过“恢复本目录配对”清除，其他填写偏好保留 |

skill 要求按阶段报告证据；“配置已保存”“本地就绪”“API 调用成功”和“浏览器已连接”分别验收。未执行或失败的步骤保持待处理状态。完整操作见[首次初始化与验收](../skills/jev-profile/references/onboarding.md)。

## 本机验证

- 最终 Python 回归 **150 项通过**，覆盖四种模型协议的配置与探测、缺密钥、不可读密钥文件、非交互终端、无法隐藏输入、旧环境覆盖、无效 URL / 端口、profile 校验和服务身份不一致等情况。
- `npm test` 的 **25 组浏览器命令全部通过**；`test:widgets` 两组控件测试通过。使用隔离的 Edge 浏览器、虚构表单和本机 HTTP fixture。安装器与 URL 校验最后调整后，再次通过全部 Python 测试和首次安装端到端测试。
- 新增 `tests/onboarding.cjs`：在含空格的全新临时目录安装 skill，以虚构密钥运行配置向导，清点单份虚构简历、建立并校验 profile，探测本机模拟 Jev / LLM，启动真实 Python bridge，完成设置页配对与旧配对恢复，最终由真实扩展经 bridge 填入虚构表单。未处理同意声明，也未提交表单。
- 端到端测试通过替身输入执行配置向导，并验证安装后的资料工具；它不等于真人交互终端验收，也不验证 agent 对任意 PDF / Word / 扫描件的提取质量。不同材料的读取覆盖与事实冲突仍须按 skill 单独核对。
- skill 格式检查、Markdown 本地链接、差异格式、公开文件扫描及安装包白名单核对通过。个人身份专项扫描未发现新增泄露；真实资料、密钥、运行记录和配对配置仍被排除。

本次没有使用真实用户的 API key、求职资料或浏览器会话，没有调用付费模型。模拟服务验证协议与连通链路，不能替代新用户使用本人账户执行 `--probe-models`；真实供应商认证、额度、模型权限和网络可用性以该次实测为准。远端 Ubuntu / Chromium 检查结果以对应提交的 GitHub Actions 为准。
