# 首次初始化与验收

本 skill 是 agent 的工作指引。完整运行仍需要插件源码目录、Python 3.9+、桌面 Chrome / Edge、用户自己的 Jev API 和生成模型 API，以及真实求职材料。安装 skill 不等于安装浏览器扩展，也不附带作者的账号、模型额度或 profile。

## 1. 识别安装与两个目录

确认用户的**插件根目录**（包含 `bridge/server.py`、`scripts/configure.py`、`scripts/doctor.py`、`extension/manifest.json`）和**求职材料目录**。先看已有上下文，缺失时才询问路径；不要把本 skill 的安装目录当作插件根目录。

只有 skill、没有完整插件时，取得公开源码 `https://github.com/chanchanpin-official/jev-resume-autofill`，或让用户指定现有副本，再继续。使用包含 `doctor.py` 的 0.2.4 或更高源码；旧 Release 不会因安装新 skill 自动升级。不要将私人旧版与公开版的扩展、服务、profile 混用。

在插件根目录运行 `python3 scripts/doctor.py --json`。首次运行缺配置或缺 profile 是正常的待处理状态，退出码非零；按返回项目处理，不复制任何人的配置。若本机已存在多份同名 skill，只更新当前选中的副本，避免另一份旧版本继续生效。

资料目标默认是本插件的 `profile/profile.json`。若用户已有 `JEV_PROFILE_PATH` 或明确使用 `--profile`，确认目标路径，后续生成、校验、doctor 与 bridge 都使用同一文件；不要静默写入默认路径后继续读取旧资料。只检查所需的路径设置，不输出整个环境或配置文件。

## 2. 用户配置 Jev 和 LLM

向用户说明需要两类服务：Jev 负责事实 / 选项匹配，LLM 负责有依据的文字回答；Codex / ChatGPT 订阅本身不会替插件提供这些 API 凭据。

在用户自己的交互终端中进入插件根目录，运行 `python3 scripts/configure.py`。用户在不回显的提示中输入密钥；不要要求用户在聊天或命令参数中发送密钥，也不要用 agent 的标准输入代填真实 key。尚未有 key 时，给出 Jev 官方文档 / 服务商控制台的获取方向并明确该项待完成，不能用测试 key 冒充配置完成。配置指导见插件根目录 `docs/API-CONFIGURATION.md`。

确认 Jev base URL / model、LLM 协议 / base URL / model。云 API 需要自己的有效 key；本机 loopback 的无鉴权 LLM 可留空。向导拒绝缺必需字段及带凭据的 URL，不完整时保留原配置。用户使用 `_FILE` 密钥文件或环境变量时，可保留其方式并跳过向导，用 doctor 检查有效配置。

同名环境变量优先于配置文件。向导检测到相关环境变量时会列出**变量名**并停止，避免“新配置已保存、旧 key 实际生效”。不要输出变量值或改写用户的全局 shell 文件。用户若改用文件配置，应在自己的当前终端取消相关变量，再运行向导、doctor 和服务；若启动脚本会重新加载这些变量，应核对启动环境。配置改变后重新验收实际服务。

配置等待期间，可先整理用户已授权的求职材料。

## 3. 建立真实 profile

按本 skill 正文的资料流程，使用**本 skill 安装目录**下的 `scripts/inventory.py` 和 `scripts/validate_profile.py`，把输出写到**插件根目录**的 `profile/`。实际命令需用带引号的完整路径，适应空格路径；Windows 中 `python3` 可换为 `py -3`。

阅读所有相关材料，保存来源清单、冲突 / 缺失说明和已校验的 `profile.json`。没有材料时，请用户提供简历或明确事实，不能用仓库教学示例完成真实初始化。资料保存成功后，检查姓名 / 联系方式、经历身份和日期，并移除已补齐事实对应的过期未知标记。告知用户仍需核对的具体事项，不把格式检查当成事实真实性认证。

## 4. 自检与 API 实测

先运行 `python3 scripts/doctor.py`，要求 Python、Jev 配置、LLM 配置和 profile 均通过。该步骤不调用模型，退出码 0 只表示本地就绪。

若用户要求完整初始化 / 验证可用，说明下一步会向用户配置的两个 API 发送固定虚构内容、可能产生少量费用，然后运行 `python3 scripts/doctor.py --probe-models`。仅创建 / 更新 profile 的请求不授权该测试；用户要求离线或拒绝 API 调用时跳过并明确“未实测”。探测只检查端点、认证、模型响应及 JSON / 来源格式，不发送个人 profile；不查询模型列表来代替实际调用，也不自动换模型或供应商。

失败时按错误处理：401 / 403 检查 key 与权限，429 检查额度 / 限流，404 检查 base URL / 协议 / model，响应校验失败检查协议或 JSON mode。一次失败后不要循环调用；修改配置后再测。不要回显供应商响应正文或密钥。

## 5. 服务、配对和扩展

在用户可持续保留的本机终端中运行 `python3 -B bridge/server.py`，保持该终端打开。不把可能随 agent 回合退出的临时子进程当作长期安装结果。已有服务先检查所属目录与使用情况；不要杀掉其他工作区的服务。端口占用时可换 `--port 17322`，后续 doctor 也用同一 `--port`。

服务创建空 profile 仅用于首次占位，不会生成真实履历；步骤 3 应已经完成。服务还生成本目录 `.runtime/bridge-token` 和 `extension/local-config.js`，API key 不进入扩展。

在另一个终端运行 `python3 scripts/doctor.py --bridge`，确认配对认证、版本、profile 路径及服务进程中的配置就绪。若使用 `--profile`，doctor 也传相同路径；此模式的路径须经过本人授权。服务端旧版本、目录混用、环境差异或资料路径不一致都不能算通过。

在 `chrome://extensions` 或 `edge://extensions` 打开开发者模式，加载本目录 `extension`。已有安装则重新加载，并在设置页点击“检查连接”，确认 profile、Jev、生成模型三项状态。浏览器保存过旧配对设置时，核对所加载目录，重载扩展后，在设置页点击“恢复本目录配对”以移除旧地址 / 令牌覆盖。不要把 API key 填入配对令牌框。

## 6. 交付与首次使用

交付按实际证据报告：skill 可发现、完整源码路径、API 本地配置、API 实测、profile 校验 / 人工核对、bridge 配对检查、浏览器设置页连接。未执行或失败的项写为待处理，并给出下一条具体操作，不用一个笼统“安装成功”覆盖全部阶段。仅当上述初始化步骤都完成，才说“已可开始首次填写”。

之后由用户选择岗位、登录并打开申请表，主动点击“开始填写”。查看人工接手清单，核对生成文字、上传附件、处理声明并自行提交。安装验收不授权对真实网站执行填写或投递；用户要求首次填表时才继续。所有本机真实配置与资料留在被 Git 忽略的目录，不放进安装后的 skill 或公开仓库。
